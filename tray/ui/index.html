Why

What leaves this machine

No accounts, no telemetry

Framekeep has no server. It never reports what you record, open or approve.

One thing is downloaded, and only when you ask

The speech model, from Hugging Face, on the download you start in Transcription. Nothing else on this machine makes a network request.

Frames reach your AI only when it asks for them

Approving a recording unlocks it. Your AI still has to request it by path, and it only ever receives frames you have seen.

On this machine

The clipboard is read on your paste, and never watched

Two ways in: the paste you press, and the shortcut you press. There is no background copy of either.

Why there is no slider

Every number above was measured on real screen recordings, and the plausible-looking values are the wrong ones — a higher scene threshold turns frame selection into a fixed-interval sample that misses the moment you were pointing at.

Works with your AI

Designed for Claude Code, Cursor, Codex, and any MCP-compatible client.

  1. 1Paste or drop a screen recording.
  2. 2Framekeep reads the frames and the speech, on this machine.
  3. 3You review what it found and hide anything that shouldn't leave.
  4. 4Ask your AI about the recording. Nothing reaches it until you do.

Connect your AI

Pick the folder you work in

Framekeep writes the MCP config there itself — no terminal, nothing to install. Claude Code, Cursor and VS Code read it when they start.

Install Node.js first

The connector your AI client starts runs on Node.js 20 or later — nodejs.org has the installer. The command below needs it too.

Run this once, in the folder you work in

It writes the MCP config for Claude Code, Cursor and VS Code into that folder. What it writes points straight at Framekeep, so your client never has to find npx again.

npx framekeep-mcp init

Then restart your AI client

It will ask you to approve Framekeep the first time. Using Codex? Add --global --client codex.
